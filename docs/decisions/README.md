# 決策紀錄(ADR)

這個目錄記錄「會約束未來的選擇」,讓之後的 session 知道現狀為什麼長這樣,
不會無意間推翻已定的決策,也不會重跑一遍已經做過的評估。

## 什麼時候要寫

判準只有一條:**未來的 session 想推翻這個選擇,成本高嗎?**

- 高 → 要寫。例:選了框架 / ORM、定了資料 schema、定了 API 形狀、
  挑了測試框架、立了跨檔案的慣例、決定「不做」某件事。
- 低 → 不寫。例:變數命名、單一檔案內部的實作方式、一次性腳本。

## 怎麼寫

1. 取號:看本目錄現有最大編號 +1,四位數(0002、0003…)。
2. 複製 `0000-template.md`,檔名 `NNNN-<英文短槽名>.md`。
3. 三個欄位各寫滿、各不超過 4 行。寫不出「代價」欄 = 你還沒想清楚,回去想。
4. 決策被推翻時:**不刪舊檔**,把舊檔狀態改成「已被 NNNN 取代」,新檔說明為何推翻。

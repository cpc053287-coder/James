# 0003:本 session 讀不到的外部環境資訊,一律記入 docs/context/ 並標註可信度界線

日期:2026-08-02
狀態:生效

## 情境

使用者長期把這個雲端 session 當成跨專案的架構討論樞紐,但多數專案(`C:\COWORK\*`、
`C:\ESH`、OCR pipeline)都在他的 Windows 本機,session 無存取權。這類資訊過去只散落在
對話裡與 `STATE.md` 的「地雷與教訓」,session 一結束就消失,下一個 session 得重問一次。
更危險的是:當這些資訊被寫成一般文件,後續 session 容易誤以為是本 session 親自核實過的事實,
違反鐵律 8。

既有的三個分類都不適合:`STATE.md` 是單一 session 的交接快照(會被覆蓋)、
`todo.md` 是待辦、`docs/decisions/` 是決策紀錄。外部環境盤點是持續累積的參考資料,
需要第四個位置。

## 決定

本 session 無法直接存取、但需要跨 session 保留的外部環境資訊,寫入 `docs/context/`。
每份此類檔案的開頭必須有「可信度界線」段落,寫明:資料來源為何、本 session 實際看到了什麼、
沒看到什麼,並把推論與事實分開標示。

## 理由與代價

把「資料來源與可信度」放在檔案開頭而非結尾,是因為弱模型 session 常只讀前幾行就開始動手;
界線寫在最前面才擋得住「拿推測當事實去改別人的程式碼」這個具體失敗。

代價:多一個目錄要維護,且這類檔案天生會過期(本機檔案結構隨時在變)。因此每份檔案都要
標「最後更新」日期與資料來源,讓後續 session 能判斷是否該重新向使用者索取。
放棄的選項是全部塞進 `STATE.md`——那會讓交接檔無限膨脹,且 STATE.md 的語意是
「上一個 session 的狀態」,不是「長期參考資料」。
